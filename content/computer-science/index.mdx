# Computer Science

This domain collects the systems-level foundations behind practical software work: version control, algorithms, operating systems, architecture, languages, networking, databases, security, and distributed systems.

## What are we learning?

We are learning how computing systems are built from first principles and how professional developers reason about them in real projects. The first authored cluster is version control and collaboration: Git, GitHub, and Bitbucket.

## Why does it matter?

Computer science becomes useful when it explains the tools engineers use every day. Git is a content-addressed history system. GitHub and Bitbucket are collaboration platforms around Git. Together they connect local work, review, automation, governance, and release operations.

## What problem does it solve?

This landing page solves the discovery problem. The deep content exists under this domain, so the page should make the most important authored tracks visible immediately instead of hiding them behind the generic taxonomy.

## Prerequisites

Start with the version-control tracks if you want practical engineering leverage first. No advanced math is required for Git, GitHub, or Bitbucket, but command-line comfort helps.

## Internal workings

The Computer Science domain is generated from `atlas/taxonomy.json`, but authored landing pages can surface the tracks that are ready for real use. The source files remain MDX so the content can be reviewed, edited, rendered, and versioned.

## Design decisions

The domain should not behave like a marketing page. It should act like a map: show the available authored material first, then let the full taxonomy expand over time.

## Alternatives

An alternative is to keep only broad domain links and rely on the sidebar. The screenshot showed why that is weak: users can reasonably think the Git and GitHub material does not exist.

## Common misconceptions

- "If a page is in the repo, users will find it." Important authored tracks need direct entry points.
- "Git, GitHub, and Bitbucket are the same topic." Git is the version-control engine. GitHub and Bitbucket are collaboration platforms around Git.
- "The top navigation is enough." Top navigation shows domains, not the deeper authored track content.
